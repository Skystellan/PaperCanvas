# ChatGPT 网页桥接验证

日期：2026-09-16。

> 历史实验记录。当前方案已改为论文右侧内嵌 ChatGPT 网页，并在本地保存每篇论文的多个对话链接。以下自动上传/消息回传方案不再是当前实施计划，具体使用方式见 README。

## 已验证

通过 Codex 浏览器工具操作已登录的 Chrome，在独立的 ChatGPT 临时聊天中测试。用户手动上传 W3C 的公开测试文件 [dummy.pdf](https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf)，随后由浏览器工具填写问题、点击发送并读取可见回复。

本地使用 pypdf 核对：文件为一页，正文为 `Dummy PDF file`。

| 测试 | 可见结果 |
| --- | --- |
| 附件就绪 | 输入区出现 `dummy.pdf` PDF 附件卡片 |
| 要求返回附件正文 | `Dummy PDF file`，与本地提取结果一致 |
| 不重新上传，追问单词数和第二个单词 | `{"word_count":3,"second_word":"PDF"}` |
| 完成状态 | 停止回答按钮消失，回复操作按钮出现 |

结论：手动上传 PDF 后，浏览器自动提问、读取回答和继续同一对话的基本链路可行。

## 验证边界

- 自动上传未通过：Chrome 浏览器工具的文件选择器返回 `Not allowed`，本轮由用户手动上传。没有改变扩展权限。
- 此文件很简单且公开，结果一致并不能独立证明模型实际调用了附件解析，也不能证明页面视觉理解能力。
- 第二轮可以使用第一轮回答完成，因此只证明对话连续性，不证明第二轮重新访问了附件。
- 尚未验证图表、公式、长论文、流式回传、取消、重启恢复、登录失效及网页变动。
- 本次使用的是 Codex 的浏览器工具，尚未实现可由 PaperCanvas 独立运行的浏览器桥接，也未修改现有 AI 接入。

## 当时拟议的 App 接入范围（已被替代）

下一步应实现一个独立的网页接入原型：App 选择论文并发起问题，桥接绑定一个专用 ChatGPT 页面，确认附件就绪后发送，读取该次回答回传 App。首版允许用户手动上传；自动上传单独验证。网页会话必须与 App 对话明确绑定，已有输入草稿不能被静默覆盖，提交后发生超时不能自动重发。

MCP 不是此链路的必需组件。先验证 App 到浏览器的独立运行方式，再考虑是否需要提供 MCP 接口。
