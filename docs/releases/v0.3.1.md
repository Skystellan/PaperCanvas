# PaperCanvas v0.3.1 — GitHub badges and AI code reviews

Spot papers with recorded GitHub implementations directly on the canvas, refresh repository Stars on demand, and ask your connected AI client to verify code associations with source evidence.

在画布上直接识别已关联 GitHub 代码的论文，打开时刷新 Stars，并让已连接的 AI 客户端查证新论文或已有论文的代码仓库、保存判断依据。

## What changed / 更新内容

- **GitHub badges:** cards show a small GitHub icon and known Stars only when a repository is recorded. Papers without a repository have no icon. Click the badge to inspect, edit or open the repository; select a card to add a missing link.
- **Lazy Stars refresh:** opening the repository dialog requests the current count from GitHub and saves it. Failures retain the previous count; loading the canvas does not request every repository.
- **One AI code-review interface:** `save_paper_code_reviews` handles both newly imported and existing papers. AI clients use their own search and reading tools to verify implementations, then save official code, third-party reproduction, not found or explicitly not released, together with a source URL, explanation and timestamp. Reviews preserve the layout, reject stale repository edits and cannot erase an existing link merely because a search found nothing.
- **Evidence on the canvas:** repository dialogs show the review conclusion and source. Papers reviewed without a repository remain icon-free; select them and choose **查看代码审查** to inspect the findings. Refreshing Stars keeps evidence; manually replacing the repository clears evidence tied to the old link.

- **GitHub 标识：** 有仓库的节点右上角显示 GitHub 图标和已知 Stars；无仓库不显示图标。点击图标可查看、修改或打开仓库，选中节点可补充链接。
- **按需刷新 Stars：** 每次打开仓库弹窗时从 GitHub 获取并保存最新计数；失败保留旧值，载入画布不会批量请求。
- **统一 AI 代码审查接口：** 抓取新论文与审查已有论文共用 `save_paper_code_reviews`。AI 使用自身搜索和阅读能力查证后，保存官方代码、第三方复现、未找到或明确未发布的结论，以及来源链接、说明和时间。不会重排画布，也不会用过期结果覆盖刚修改的仓库链接。
- **保留查证依据：** 仓库弹窗可查看结论与依据。无仓库的已审查论文仍不显示图标，选中后通过 **查看代码审查** 查看记录。未找到代码不等于未开源；AI 结论仍需结合来源判断。

## Try it / 开始使用

Update PaperCanvas and keep it open. If your MCP client already points to the application's bundled `papercanvas-mcp.mjs`, no configuration change is needed: restart the MCP connection or client to load the new tool. External MCP clients still require Node.js 22.12+. The embedded ChatGPT webpage is not connected to the local MCP tools.

更新后保持 PaperCanvas 打开。若 MCP 已指向应用包内的 `papercanvas-mcp.mjs`，无需修改配置，重启 MCP 连接或客户端以加载新工具即可。然后对已连接的 AI 说：“审查当前画布论文的代码公开情况，核对 GitHub 关联并保存依据。”也可要求找论文时一并查证代码。内嵌 ChatGPT 网页尚未接入本地 MCP。

See [MCP setup and workflow / MCP 连接与使用说明](https://github.com/Skystellan/PaperCanvas/blob/v0.3.1/mcp/README.md).

## Validation / 验证范围

Tests cover shared review writes for new and existing papers, source validation, atomic rollback, stale-link conflicts, persistence after reopening, legacy import undo snapshots, conditional icons and one Stars request per dialog opening. Packaged desktop checks exercise the real MCP → Electron → Rust path with isolated profiles and synthetic papers. These checks validate the software flow, not the correctness of every AI judgment or ongoing availability of GitHub.

验证覆盖新旧论文共用审查写入、来源校验、整批回滚、旧链接冲突、重启持久化、旧版导入撤回记录、图标显示与每次打开仅请求一次 Stars。桌面测试使用隔离资料和合成论文验证真实 MCP → Electron → Rust 流程；不代表每次 AI 查证结果均正确，也不保证 GitHub 持续可用。

`SHA256SUMS.txt` covers release assets. `latest-linux.yml`, `latest.yml`, `.blockmap` and the signed `appcast.xml` support in-app updates.
